## 狱策 · 早期 v0.2 原型

已找回用户提供的 TalosHelper v0.3 策略、训练报告及应用字节码。接续该旧版的 **0.3.1 离线更新**、安装方法及验证范围见 [legacy-update/README.md](legacy-update/README.md)。它复用原完整目录，新增 EXE 与旧 EXE 并排保留。下文说明的是此前独立实现的 v0.2 原型，两者的模型和收益不能混用。

Windows 本地策略助手，面向普通 20 天典狱玩法，以结算绮彩囚犯数量为目标。应用内置本项目独立实现的近似规则、策略和离线识图组件，支持截图、手工核对、下一步比较、置顶与精简悬浮窗。只给建议，由你在游戏中执行操作。

**Windows ZIP 解压后即可运行，无需安装 Git，也不需要联网。首次识图需要手动标定位置、录入并学习已核对的棋盘；应用尚未验证中文实机识别准确率。**

## Windows 使用

完整解压 Windows x64 ZIP，保留同目录的资源文件，运行其中的应用程序。游戏使用无边框或窗口模式；独占全屏可能无法显示浮层，最小化窗口可能无法截图。

1. 刷新来源列表，明确选择游戏窗口，点击“截图并分析”，或导入、拖放、粘贴一张完整典狱截图。首次尚未学习时，应用会保留画面供标定。
2. 点击“校准牢房位置”，从左上角 **01 审讯室**开始，沿棋盘顺时针依次点击全部 **16 个房间中心**，保存位置。
3. 点击“创建空棋盘 / 手工录入”，逐格对照当前截图，填写未开启、空房、巢穴或囚犯，以及囚犯种族和阶级。标定位置本身不会教会软件识别囚犯。
4. 确认截图与棋盘逐格一致，勾选“我已逐格核对本张截图与棋盘”，再点“学习已核对样本”。随后用“重新识别当前截图”检查结果。遇到新的房间外观、种族或阶级时，继续纠正并学习样本。
5. 手动核对天数、典狱长位置、可到达格、刑具、任务、已捕获绮彩、事件和操作阶段，再计算建议。尚未确认的信息会单独标出；按提示确认后才推荐。

你也可以直接手工录入局面并计算建议。示例局面用于体验界面，不作为截图学习样本。

调整游戏分辨率、界面缩放、截图范围或棋盘位置后，请重新检查标定。修改已保存的位置后，下一次学习会重新建立样本，可以先导出原配置留存。仅学习少量截图不能保证识别全部外观；识别结果仍须逐格核对。

### 分享识图样本

“导出校准 / 样本 JSON”会保存 `torchlight-vision-profile.json`，可手动发给朋友，再通过“导入朋友的 JSON”加载。文件仅含标定位置、截图尺寸与数值特征，不含原始截图。朋友应先检查自己的分辨率、界面缩放和房间位置，再用实际截图验证；不匹配时重新标定并学习。

样本保存在应用的用户数据目录。截图和分析均在本机完成，无需 API Key，也不会自动上传截图或样本。

### 日常操作

| 操作 | 快捷键 / 入口 |
| --- | --- |
| 截取已选择的来源 | `Ctrl+Alt+P` |
| 显示 / 隐藏窗口 | `Ctrl+Alt+O` |
| 展开完整界面 | `Ctrl+Alt+A` |
| 置顶、精简悬浮 | 界面右上角按钮 |
| 清除本局上下文 | “新局 / 清空局面” |

定时识别默认关闭，完成离线识图学习后可开启，间隔至少 3 秒。切换截图来源会清空旧局面；同一窗口开始下一局时也应清空本局上下文。已入库的绮彩计入“已捕获绮彩”，并按游戏现状更新原牢房，避免重复计算。

选择刑具或珍藏时，请录入实际选项及选完后返回的阶段；僭越进度、猎物标记、巢穴孵化日期等也需手动核对。当前没有中文 OCR，天数、位置、目的地、刑具、任务和阶段不能依靠截图自动读全。

## 规则覆盖与推荐边界

当前实现 **20 种刑具**：手足的命运硬币、长链脚镣、执行官的黑名册、替罪人的断头台、切开的人形棺、绞首绳、疯兽的倒刺项圈、复仇者之匣、拥挤兽笼、锈锯、棘刺铁鞭、鼠头串：硕鼠、狂兽的剧痛口枷、恶欲铁钳：巨象、蠕动铁盒：硕鼠、遗落的钥匙串、灼痛的烙铁、挑拣钩、重刑铭牌、火刑柱。

捕兽夹主动寻猎、“有福同享”“宿敌”“同罪移押”、特殊开局及其他标注“待支持”的机制不在当前验证范围。录入这些机制或未知刑具、事件时，应用会停止推荐，不能忽略其效果继续计算。

规则采用僭越第二阶段一名升两阶、煽动增加一个事件、口枷人数阈值三名。口枷按吞噬后人数判断仍是未验证假设。开门、替换、事件概率与部分效果顺序使用明确的练习假设，详情见训练报告和应用内报告。

建议由有限采样前瞻比较各动作在当前模型中的期望绮彩数量，未知牢房会重新抽样。**这不能证明真实游戏中的绝对最优，也不代表游戏实测收益。** Windows 游戏窗口、DPI、动画遮挡和中文截图仍需实机验证；本地功能测试不能替代这些验证。

## 本次训练

训练采用策略参数搜索与完整对局模拟，累计 **102,100 局**，最多 4 个工作线程。搜索、验证和留出使用分离种子；最终以 20,000 个配对种子比较初始策略和已选候选 `open-low`。

| 原创近似模型内的独立留出结果 | 平均绮彩 / 局 |
| --- | ---: |
| 本地初始策略 | 2.34295 |
| 候选 `open-low` | 2.47745 |
| 候选减初始策略 | +0.13450 |

配对差值的 95% 置信区间为 **[0.11205, 0.15695]**。该结果支持在本模型、该实验配置下使用此候选，不能外推为真实游戏的收益提升。模型为 `models/trained-policy.json`；完整配置、假设与统计见 [训练报告](reports/training-report.md) 和 `reports/training-report.json`。

更改规则或候选后，应使用新版本的独立留出种子，不能反复挑选同一留出集的结果。

## 从源码开发

需要 Node.js 24 和 npm，无需 Git。首次安装依赖及 Electron 开发运行时需要下载；安装完成后，应用的规则、识图和推荐均可离线运行。

```sh
npm ci
npm run setup
npm start
```

`setup` 仅安装缺失的 Electron 二进制，使用其官方安装流程和校验和；已有安装会复用。它不会下载第三方模拟器、识图特征或游戏图片。

```sh
# 仅绑定本机回环地址的浏览器开发界面；窗口捕获和全局快捷键需桌面应用
npm run dev

# 复现策略训练与独立评估
npm run train -- --threads 4 --train-games 2000 --validation-games 6000 --holdout-games 20000

# 自动检查与 Windows x64 ZIP 打包
npm test
npm run dist:win
```

打包过程可能下载构建依赖；生成的 ZIP 包含运行所需组件，使用时不需要 Git 或网络。第三方依赖与资料说明见 [THIRD_PARTY.md](THIRD_PARTY.md)。

## 目录

- `desktop/`：窗口、来源选择、截图、快捷键及后台任务。
- `renderer/`：中文棋盘、16 点标定、样本学习与建议界面。
- `lib/offline-engine.js`、`lib/offline-solver.js`、`lib/offline-vision.js`：自有近似规则、策略与离线特征识别。
- `lib/service.js`：局面校验、样本保存与分析接口。
- `scripts/`、`test/`：开发安装、训练、打包辅助和自动检查。
- `models/`、`reports/`：本版本模型与训练记录。

云任务使用现有隔离检出即可，无需另建 Git worktree。开发缓存和安装产物放在忽略目录，运行时不加载第三方参考检出。
