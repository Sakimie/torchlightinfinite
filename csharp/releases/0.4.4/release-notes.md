# 典狱助手 0.4.4 · 日志跟随与整局模拟测试版

在现有 C# 深色界面和便携版上增加本地日志跟随与整局模拟。运行时使用自己的 C# 实现，没有接入第三方在线分析网页，也不复制第三方未授权源码或识图数据。

## 新增能力

- 选择本机游戏日志后可主动开启自动跟随。检测到典狱操作后先清除旧建议，合并连续事件并等待动画，再获取所选游戏窗口的新画面并离线识别。跟随每次启动默认关闭。
- 自动模式要求明确选中的游戏窗口有效、可见且处于前台。窗口最小化、切到后台、日志中断或持续不稳定时会暂停或放弃本次截图；仍可使用 F8、导入和粘贴截图。
- 增加整局模拟模式：从核对后的局面出发，对候选操作分别模拟至第 20 天，比较终局入库绮彩总数。候选使用共同随机种子，只统计全部候选都完成的轮次，显示实际样本数和抽样误差。
- 保留明确标注的即时规则评分模式。整局模拟出错或预算不足时提示原因，不会把即时评分伪装成模拟结果。
- 悬浮窗同步等待截图、待核对、计算中和建议状态。新图、编辑、换来源、停止跟随或取消分析都会使旧建议失效。

## 开始使用

1. 完整解压便携包，或在现有 0.4.2/0.4.3 便携版中导入配套签名 JSON 和更新 ZIP，完成后重启到新版本。保留原有 `data`。
2. 明确选择游戏窗口，按原流程校准 16 个房间中心。截图和识别结果仍须核对，天数、阶段、刑具、任务等控制信息需要手工确认。表格中的“已探明”表示你已确认事件有无；没有事件且已探明的门不会随机补出事件，未探明的门按模型假设采样。“已探明”不代表已经知道门内囚犯。
3. 要使用日志跟随，先在游戏中启用详细日志并重新登录，再选择实际 `.log` 文件、开启跟随。游戏客户端的具体开关名称可能不同。
4. 默认事件规则是未经国服实机验证的保守候选。没有自动触发时，可配置从本机典狱操作日志观察到的固定关键词，或继续按 F8 截图；日志只用于判断截图时机，不代表已经读出了棋盘。
5. 核对新画面后选择整局模拟并计算建议。预计数量包含当前已经入库的绮彩，误差只描述模型内抽样波动。

## 运行与更新

截图、识别、日志处理与建议计算在本机执行；不上传截图、日志、棋盘或样本。只有主动检查及下载应用更新时联网。配置、校准和更新状态仍在 EXE 旁的 `data` 目录。

完整包自带运行环境，不需要安装 Python、Node、Git 或 .NET；请保留所有旁置 DLL。已有便携启动器支持本次离线组件更新，旧 0.4.0/0.4.1 启动器仍需使用完整便携包。

## 验证范围

模拟使用本项目已有的可见信息策略和修正后的本地规则。未来工具仅从支持列表生成，开门概率、事件分布、部分效果时点与顺序仍有练习假设。未知机制需要停止推荐。未宣称真实游戏的全局最优，也未继承旧版本的训练收益或识别准确率。

此版本需要进一步验证 Windows 游戏窗口、焦点、日志事件、动画时长、DPI 和中文截图。Linux 上的编译、规则测试及包校验不能替代实机验证。交付与检查结果以配套验证报告为准。
